# زاخر | Zakher Garage

نسخة تجريبية لإدارة كراج صيانة السيارات، بواجهة عربية واتجاه RTL، متجاوبة مع الآيفون والكمبيوتر. تعمل دون مكتبات خارجية أو مفاتيح API.

## التشغيل

يلزم Node.js 22 أو أحدث (اختُبرت على 24.22.1). من مجلد المشروع:

```bash
npm start
```

افتح على الكمبيوتر `http://localhost:3000`. لا يلزم تثبيت تبعيات للتشغيل المحلي. تجهيز ملفات الاستضافة متاح عبر `npm run build`. لتغيير المنفذ: `PORT=3001 npm start` على macOS/Linux.

## على الآيفون

1. شغّل البرنامج على الكمبيوتر كما سبق واتركه يعمل.
2. وصّل الكمبيوتر والآيفون بشبكة Wi-Fi نفسها.
3. اعرف عنوان IP المحلي للكمبيوتر من إعدادات الشبكة، مثل `192.168.1.20`.
4. في Safari افتح `http://192.168.1.20:3000` مع استبدال العنوان بعنوان جهازك. اسمح باتصال الشبكة المحلية في جدار حماية الكمبيوتر عند الحاجة.
5. من مشاركة Safari اختر «إضافة إلى الشاشة الرئيسية» للوصول السريع. تحتاج هذه النسخة اتصالًا بالخادم؛ ليست تطبيقًا مستقلًا يعمل دون اتصال.

هذه الخطوات تخص التشغيل المحلي. لتجربة النسخة من الآيفون دون كمبيوتر، استخدم رابط HTTPS الذي تعرضه صفحة GitHub Pages بعد نجاح النشر، ثم اختر مشاركة ← إضافة إلى الشاشة الرئيسية في Safari. عنوان localhost في جلسة التطوير ليس رابطًا عامًا. النسخة تجريبية بلا تسجيل دخول أو قاعدة بيانات مشتركة، والبيانات تبقى في المتصفح.

## الاستخدام اليومي المبسّط

القائمة الأساسية هي **الورشة، الفواتير، العملاء، المزيد**. ستجد قطع الغيار والحسابات والنسخ الاحتياطي داخل «المزيد».

1. في **الورشة** اضغط **استلام سيارة**. سجّل العميل والسيارة وسبب الزيارة في نموذج واحد، أو اختر سيارة مسجلة سابقًا.
2. يمكن إضافة التكلفة وقطع الغيار من القسم القابل للفتح في النموذج، أو تركها صفرًا عند الاستلام. بعد الحفظ افتح **الفاتورة والمزيد ← تعديل الصيانة والتكلفة** لإكمالها أو تصحيحها.
3. استخدم مرشحات **داخل الورشة، جاهزة للتسليم، كل السيارات** للعثور على السيارة، أو ابحث بالاسم أو اللوحة.
4. عندما تنتهي الصيانة اضغط **السيارة جاهزة**. تظهر معاينة رسالة الجاهزية لتراجعها، وتنتقل السيارة إلى «جاهزة للتسليم».
5. اطبع الفاتورة أو سجّل الدفع من **الفاتورة والمزيد** في بطاقة السيارة.

استلام السيارة دون تكلفة ينشئ أمرًا وفاتورة بقيمة صفر ضمن البيانات الحالية، ويمكن تعديلها لاحقًا. لا يمكن تعديل فاتورة مدفوعة؛ ألغِ تسجيل الدفع أولًا، عدّل البيانات، ثم سجّل الدفع من جديد. تعديل قطع الفاتورة يعيد الكمية السابقة إلى المخزون ويخصم الجديدة، ويحافظ على أسعار القطعة المحفوظة إذا بقيت القطعة نفسها. إعادة فتح الصيانة لا تلغي فاتورتها أو دفعتها.

## إشعارات واتساب

- اضغط **واتساب: تم الاستلام** من بطاقة السيارة لإعداد إشعار استلامها للصيانة.
- بعد تحديد **السيارة جاهزة** يمكنك مراجعة إشعار الجاهزية أو فتحه لاحقًا من **واتساب: السيارة جاهزة**.
- في المعاينة راجع اسم العميل ورقمه ونص الرسالة، وعدّل الرقم أو النص عند الحاجة. تعديل الرقم هنا يخص هذه الرسالة فقط.
- اضغط **فتح واتساب للإرسال**، ثم اضغط **إرسال** بنفسك داخل واتساب. لا تُرسل رسالة تلقائيًا عند تغيير الحالة، ولا يسجّل البرنامج أن الرسالة وصلت أو قُرئت.

تحتوي الرسالة على اسم الكراج والعميل والسيارة واللوحة ورقم أمر الصيانة. تُقبل أرقام الإمارات المحلية مثل `0501234567`، والأرقام الدولية التي تبدأ بـ `+` أو `00`، وكذلك الأرقام العربية والفارسية. أضف رمز الدولة للأرقام غير الإماراتية. يتحقق البرنامج من تنسيق الرقم؛ لا يستطيع تأكيد أن الرقم مسجل في واتساب أو أن العميل قرأ الرسالة.

الإرسال التلقائي مستقبلًا يحتاج ربطًا رسميًا بواجهة **WhatsApp Business API** وخادمًا وبيانات اعتماد وإعداد القوالب المناسبة. هذا الربط غير موجود في النسخة الحالية، ولا تحتاج ميزة الرسائل الجاهزة الحالية إلى مفاتيح API.

## الوظائف

- تسجيل العملاء وربط سياراتهم بهم، والبحث بالاسم والهاتف واللوحة.
- تسجيل قطع الغيار وتكلفة شرائها وسعر بيعها وتوريد كميات جديدة.
- إصدار أمر صيانة مع فاتورة، واختيار قطعة واحدة وكمية لكل أمر في هذه النسخة.
- خصم المخزون عند إصدار الفاتورة، ومنع إصدارها عند نقص الكمية.
- إصدار عروض أسعار دون خصم المخزون أو إدراجها ضمن الإيرادات.
- متابعة حالة الصيانة وتسجيل الدفع أو إلغائه، وتعديل وصف الخدمة والتكلفة في الفواتير غير المدفوعة.
- إعداد رسائل استلام السيارة وجاهزيتها مع مراجعة الرقم والنص قبل فتح واتساب.
- طباعة عروض الأسعار والفواتير بعناوين عربية وإنجليزية؛ أدخل وصف الخدمة باللغتين ليظهر باللغتين. من مربع الطباعة يمكنك اختيار PDF إذا كان جهازك يدعمه.
- تسجيل المصاريف وحساب الإيرادات وتكلفة القطع والربح التقديري والمبالغ غير المحصلة.
- تصدير واستعادة JSON مع فحص بنية الملف وتأكيد استبدال البيانات.

تظهر بيانات تجريبية عند أول فتح. لمسحها اختر «المزيد ← النسخ الاحتياطي ← مسح البيانات» ثم «مسح البيانات والبدء من جديد».

## البيانات والحسابات

تُحفظ البيانات في localStorage داخل المتصفح وعلى عنوان الموقع نفسه. تستخدم الواجهة الجديدة مفتاح التخزين السابق `zakher-garage-v1` وبنية البيانات نفسها للاحتفاظ ببيانات النسخة السابقة عند تحديث الموقع على العنوان نفسه. لا تنتقل تلقائيًا بين الآيفون والكمبيوتر أو بين المتصفحات، ولا تُرفع إلى GitHub. صدّر نسخة من صفحة النسخ الاحتياطي ثم استوردها على الجهاز الآخر عند الحاجة؛ الاستيراد يستبدل بياناته. احتفظ بالنسخ التي تتضمن بيانات العملاء في مكان خاص وخارج المستودع.

الإيرادات هي قيمة جميع الفواتير قبل ضريبة القيمة المضافة، سواء دُفعت أم لا. الربح التقديري = الإيرادات − تكلفة القطع المباعة وقت الإصدار − المصاريف. تكلفة القطع محفوظة وقت الإصدار ولا تتغير بتغيّر سعر المخزون. الضريبة التجريبية ثابتة عند 5%، والمستندات ليست فواتير ضريبية معتمدة. لا تتضمن النسخة مرتجعات أو خصومات أو سدادًا جزئيًا أو عدة قطع في الفاتورة الواحدة. تطوير الإنتاج يتطلب قاعدة بيانات ومصادقة وصلاحيات ونسخًا احتياطية مركزية وتدقيقًا محاسبيًا.

## الاختبارات

```bash
npm test
```

أربعة عشر اختبارًا تغطي خصم المخزون والضريبة وتثبيت التكلفة، استبعاد عروض الأسعار، منع نقص المخزون دون تغيير جزئي، رفض المدخلات الخاطئة، حساب الربح والتحصيل، وصحة النسخ الاحتياطية، وتنسيق أرقام واتساب وترميز نص الرسالة، وتعديل التكاليف والقطع دون تغيير جزئي أو تعديل فاتورة مدفوعة.

اختبار متصفح اختياري (يتطلب Playwright وChromium). ثبّت أداة الاختبار خارج المشروع للمحافظة على عدم وجود تبعيات تشغيل:

```bash
npm install --prefix /tmp/zakher-test-tools playwright
PLAYWRIGHT_MODULE=/tmp/zakher-test-tools/node_modules/playwright node scripts/ui-test.cjs
```

شغّل `npm start` أولًا. لاختبار استضافة تحت مسار فرعي، عيّن `BASE_URL` إلى عنوانها الكامل المنتهي بشرطة مائلة، مثل `http://127.0.0.1:3001/Zakher-/`. يستخدم الاختبار Chromium المثبت في `/usr/bin/chromium`؛ يمكن تعيين `CHROMIUM_PATH` أو استخدام `CDP_URL` لمتصفح اختبار يعمل مسبقًا. الاختبار يستخدم سياق متصفح منفصلًا ولا يمس بياناتك. يغطي استلام سيارة جديدة أو مسجلة والفاتورة والمخزون والدفع وإتمام الصيانة وعرض السعر والحفظ بعد التحديث والمصروف والطباعة والتصدير والاستيراد وعرض 390 بكسل، إضافة إلى معاينة رسائل واتساب والتحقق من الرقم والنص والرابط دون إرسال رسائل فعلية. محاكاة عرض الهاتف لا تعادل اختبار Safari على آيفون فعلي.

## حفظ التعديلات في GitHub

من مجلد المشروع، راجع الملفات أولًا ثم أنشئ فرعًا واحفظها:

```bash
git status
git switch -c feature/zakher-demo
git add .gitignore README.md package.json server.js index.html app.js domain.js style.css tests scripts
git commit -m "Add Zakher garage demo"
git push -u origin feature/zakher-demo
```

إذا طلب Git اسمك وبريدك، اضبط `git config user.name` و`git config user.email` محليًا بهويتك الصحيحة ثم أعد أمر commit. لا تضع مفاتيح أو كلمات مرور داخل الملفات. افتح المستودع `mhmdro/Zakher-` على GitHub ثم أنشئ Pull Request إلى `main` إذا كانت موجودة. إذا كان المستودع بلا أي commits أو فرع main، يمكنك بعد أول commit استخدام `git branch -M main` ثم `git push -u origin main` لإنشاء أول فرع بدل أمر push السابق.

حفظ الكود في GitHub وحده لا ينشر الموقع ولا يحفظ سجلات العملاء. نشر الموقع يتطلب تفعيل GitHub Pages ورفع ملفات الاستضافة كما في القسم التالي.


## النشر على GitHub Pages

المشروع يعمل كملفات ثابتة دون خادم Node.js في الاستضافة. جهّزها بالأمر:

```bash
npm test
npm run build
```

ينتج `dist/` وفيه فقط `index.html` و`app.js` و`domain.js` و`style.css` و`.nojekyll`. لا يتضمن التصدير بيانات المتصفح أو سجلات العملاء التي أدخلتها أو ملفات الخادم والاختبار أو أي أسرار وبيانات اعتماد. البيانات المرفقة في المصدر أمثلة تجريبية؛ لا ترفع ملفات النسخ الاحتياطية التي تتضمن بيانات حقيقية إلى المستودع. مسارات الأصول نسبية لتعمل تحت مسار المستودع.

يحتفظ فرع `main` بالمصدر، وفرع `gh-pages` بملفات الموقع الجاهزة. بعد رفع فرع `gh-pages` افتح إعدادات المستودع → Pages، واختر:

- Source: **Deploy from a branch**
- Branch: **gh-pages**
- Folder: **/ (root)**

احفظ الإعدادات وانتظر نجاح بناء Pages. يظهر الرابط الفعلي في صفحة الإعدادات نفسها. لا يعني رفع الفرع وحده أن الموقع أصبح متاحًا؛ يجب نجاح بناء الاستضافة. لا تغيّر خصوصية المستودع أو تشترك في خطة مدفوعة تلقائيًا؛ تحقق من توفر Pages في خطة حسابك إذا كان المستودع خاصًا.

لتحديث الموقع لاحقًا، احفظ تغييرات المصدر في `main`، أعد الاختبارات و`npm run build` ثم حدّث محتويات فرع `gh-pages` بالملفات الخمسة. الكود المنشور لا يزامن بيانات المتصفحات؛ استخدم التصدير والاستيراد لنقلها.
