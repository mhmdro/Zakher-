# زاخر | Zakher Garage

نسخة تجريبية لإدارة كراج صيانة السيارات، بواجهة عربية وإنجليزية مع RTL وLTR، متجاوبة مع الآيفون والكمبيوتر. تعمل دون تثبيت تبعيات تشغيل للوظائف الأساسية؛ الخطوط والشعارات ومحرك قراءة VIN مضمّنة محليًا. بحث بيانات VIN خدمة خارجية اختيارية، وربط AI غير متصل حاليًا.

## التشغيل

يلزم Node.js 22 أو أحدث (اختُبرت على 24.22.1). من مجلد المشروع:

```bash
npm start
```

افتح على الكمبيوتر `http://localhost:3000`. لا يلزم تثبيت تبعيات للتشغيل المحلي. تجهيز ملفات الاستضافة متاح عبر `npm run build`. لتغيير المنفذ: `PORT=3001 npm start` على macOS/Linux.

## على الآيفون

1. شغّل البرنامج على الكمبيوتر كما سبق واتركه يعمل.
2. وصّل الكمبيوتر والآيفون بشبكة Wi-Fi نفسها.
3. اعرف عنوان IP المحلي للكمبيوتر من إعدادات الشبكة، مثل `192.168.1.20`.
4. في Safari افتح `http://192.168.1.20:3000` مع استبدال العنوان بعنوان جهازك. اسمح باتصال الشبكة المحلية في جدار حماية الكمبيوتر عند الحاجة.
5. من مشاركة Safari اختر «إضافة إلى الشاشة الرئيسية» للوصول السريع. تحتاج هذه النسخة اتصالًا بالخادم؛ ليست تطبيقًا مستقلًا يعمل دون اتصال.

هذه الخطوات تخص التشغيل المحلي. لتجربة النسخة من الآيفون دون كمبيوتر، استخدم رابط HTTPS الذي تعرضه صفحة GitHub Pages بعد نجاح النشر، ثم اختر مشاركة ← إضافة إلى الشاشة الرئيسية في Safari. عنوان localhost في جلسة التطوير ليس رابطًا عامًا. النسخة تجريبية بلا تسجيل دخول أو قاعدة بيانات مشتركة، والبيانات تبقى في المتصفح.

## الاستخدام اليومي المبسّط

القائمة الأساسية هي **الورشة، الفواتير، العملاء، المزيد**. ستجد قطع الغيار والحسابات والعمال والرواتب والتذكيرات والنسخ الاحتياطي داخل «المزيد».

اضغط اسم الكراج أو الشعار أعلى الصفحة للرجوع إلى الرئيسية «الورشة». يعيدك الرابط إلى السيارات داخل الورشة ويمسح البحث الحالي دون إعادة تحميل الموقع أو تغيير بياناتك. يعمل شعار القائمة الجانبية بالطريقة نفسها على الكمبيوتر.

1. في **الورشة** اضغط **استلام سيارة**. سجّل العميل والسيارة وسبب الزيارة في نموذج واحد، أو اختر سيارة مسجلة سابقًا.
2. يمكن إضافة التكلفة وقطع الغيار من القسم القابل للفتح في النموذج، أو تركها صفرًا عند الاستلام. بعد الحفظ افتح **الفاتورة والمزيد ← تعديل الصيانة والتكلفة** لإكمالها أو تصحيحها.
3. استخدم مرشحات **داخل الورشة، جاهزة للتسليم، كل السيارات** للعثور على السيارة، أو ابحث بالاسم أو اللوحة.
4. عندما تنتهي الصيانة اضغط **السيارة جاهزة**. تظهر معاينة رسالة الجاهزية لتراجعها، وتنتقل السيارة إلى «جاهزة للتسليم».
5. من **الفاتورة والمزيد ← الدفعات والمتبقي** سجّل المبلغ المستلم وتاريخه وملاحظته، أو سجّل كامل المتبقي. يظهر المدفوع والمتبقي في البطاقة والفاتورة المطبوعة.
6. عند خروج السيارة اضغط **تسليم السيارة للعميل**. إذا بقي مبلغ، أكد التسليم مع بقاء الدين. السيارة تبقى في **كل السيارات** و**الفواتير**، وتخرج من قائمتَي داخل الورشة وجاهزة للتسليم.

استلام السيارة دون تكلفة ينشئ أمرًا وفاتورة بقيمة صفر ضمن البيانات الحالية، ويمكن تعديلها لاحقًا. لا يمكن تعديل فاتورة مدفوعة بالكامل؛ ألغِ الدفعة الخاطئة أولًا عند الحاجة إلى تصحيح. يمكن تعديل الفاتورة المدفوعة جزئيًا بشرط ألا يقل الإجمالي الجديد عن المدفوع. إلغاء دفعة يحتفظ بسجلها وتاريخ الإلغاء، ولا يحذفها من التاريخ. تعديل قطع الفاتورة يعيد الكمية السابقة إلى المخزون ويخصم الجديدة، ويحافظ على أسعار القطعة المحفوظة إذا بقيت القطعة نفسها. حالة التسليم مستقلة عن السداد؛ إلغاء حالة التسليم لا يغيّر الدفعات.

## عرض سعر لعميل غير مسجّل

من **الفواتير ← عرض سعر** اترك اختيار السيارة على **إدخال العميل والسيارة يدويًا**، ثم اكتب اسم العميل والسيارة ورقم اللوحة، والهاتف اختياري. تُحفظ هذه المعلومات داخل العرض دون إنشاء عميل أو سيارة في سجلاتك. يمكنك تعديلها لاحقًا وطباعة العرض بالعربية أو الإنجليزية أو اللغتين. لا يخصم العرض المخزون ولا يدخل ضمن الإيرادات. يظل اختيار سيارة مسجلة متاحًا من القائمة نفسها.

## العمال والرواتب

من **المزيد ← العمال والرواتب** أضف العامل وراتبه الشهري ومهنته وتاريخَي انتهاء الإقامة وبطاقة العمل. اختر شهر الراتب، ثم افتح **الراتب والدفعات والخصومات** لتسجيل ما استلمه أو خصم مع سبب. يظهر الراتب الأساسي والخصومات والصافي والمستلم والمتبقي لكل شهر، مع إمكانية إلغاء الحركة الخاطئة والاحتفاظ بسجلها.

أول حركة في الشهر تثبّت الراتب الأساسي لذلك الشهر. تعديل راتب العامل لاحقًا لا يغيّر الأشهر التي لها حركات محفوظة. يمكن تعطيل العامل بدل حذف تاريخه، وعندها تتوقف تذكيرات مستنداته. دفعات الرواتب المصروفة فقط تدخل تلقائيًا في مصاريف الكراج؛ الراتب غير المصروف والخصومات لا تُسجّل كمصروف. لا تدخل هذه الدفعات مرة أخرى كمصاريف يدوية.

## تذكيرات المستندات والمبالغ المتبقية

يظهر شريط بالتذكيرات المستحقة عند فتح الموقع أو الرجوع إليه، ويمكن مراجعتها من **المزيد ← التذكيرات والمبالغ المتبقية**. تنبيهات مستندات العمال تبدأ قبل الانتهاء بـ30 يومًا افتراضيًا، ويمكن اختيار 7 أو 14 أو 30 أو 60 أو 90 يومًا. تبقى المستندات المنتهية ظاهرة حتى تحديث التاريخ أو تعطيل العامل.

تذكير المبلغ غير المسدد يبدأ افتراضيًا بعد أسبوع من الفاتورة أو تسليم السيارة. يبقى ظاهرًا حتى تسديد المبلغ أو تأجيل المتابعة. من الدفعات اختر مدة التأجيل، أو اضغط **ذكرني بعد أسبوع** من قائمة التذكيرات لتحديد الموعد التالي. يظل المتبقي مستحقًا حتى لو سلّمت السيارة، وينخفض مع الدفعات الجزئية ويتوقف التذكير بعد السداد الكامل. يمكنك إعداد رسالة تذكير بالعربية أو الإنجليزية تتضمن الإجمالي والمدفوع والمتبقي، ثم مراجعتها وفتح واتساب للإرسال بنفسك.

هذه تذكيرات داخل الموقع، تتحدث عند فتحه أو العودة إليه ودوريًا أثناء بقائه مفتوحًا. لا ترسل إشعارات هاتف أو رسائل واتساب عندما يكون الموقع مغلقًا. التنبيهات الخارجية المجدولة تحتاج خادمًا وخدمة إشعارات مرتبطة، وهي غير مفعلة في هذه النسخة.

## لغة الواجهة والمستندات

من محدد لغة الواجهة (`#ui-language`) اختر **العربية** باتجاه RTL أو **English** باتجاه LTR. هذا الاختيار يغيّر القوائم والنماذج، وهو مستقل عن لغة رسائل واتساب. بيانات العملاء والملاحظات التي تكتبها تبقى كما أُدخلت ولا تُترجم بمجرد تغيير الواجهة.

يمكن اختيار **العربية أو الإنجليزية أو اللغتين** عند إنشاء المستند، أو اختيار لغة الطباعة من بطاقة الفاتورة أو عرض السعر. حقل **وصف الخدمة بالإنجليزية (اختياري)** يتيح كتابة وصف إنجليزي فعلي. إذا غاب هذا الوصف، يستخدم المستند الإنجليزي الوصف الأصلي كما هو؛ لا يدّعي البرنامج أنه ترجمه تلقائيًا.

الفواتير وعروض الأسعار تستخدم تصميم A4 باللون الأزرق، مع أقسام لبيانات العميل والسيارة وجدول البنود وملخص المبالغ. يظهر أسفل المستند ختم دائري باسم كراج زاخر وعبارة **مختوم إلكترونياً**، أو **Electronically stamped** في المستند الإنجليزي. الختم عنصر تصميم يُطبع مع المستند. تُحافظ أنماط الطباعة على الألوان عند الحفظ كـPDF، وقد تؤثر إعدادات الطابعة واختيار الطباعة بالأبيض والأسود على النتيجة الورقية.

يبقى الختم مع ملخص المبالغ في كتلة واحدة عند توزيع صفحات الطباعة، حتى لا يظهر منفردًا في صفحة أخيرة. الفواتير الطويلة قد تمتد إلى عدة صفحات، مع بقاء الإجمالي والختم معًا في الصفحة الأخيرة.

## ورقة الصيانة وVIN وطلب القطع

من بطاقة السيارة افتح **الفاتورة والمزيد ← الشاصي وطلب قطع الغيار**:

1. أضف VIN والسنة والمحرك والوقود عند الحاجة، أو اختر صورة واضحة لرقم الهيكل. تُقرأ صورة JPEG/PNG/WebP محليًا في المتصفح باستخدام Tesseract الإنجليزي؛ راجع VIN من 17 حرفًا لاتينيًا/رقمًا قبل طلب بيانات السيارة. لا تُرفع الصورة إلى خدمة خارجية.
2. اضغط **جلب بيانات السيارة من VIN** لطلب بحث من قاعدة **NHTSA vPIC**. يُرسل الرقم وحده، وقد تكون البيانات جزئية؛ لا تُخمّن الخانات الناقصة. الاختبار الحي من بيئة التطوير الحالية حُظر برد 403، لذلك الاتصال الخارجي غير متحقق منه هنا؛ يبقى الإدخال اليدوي متاحًا.
3. اكتب القطع المطلوبة بالعربية وبالإنجليزية، سطرًا لكل قطعة. **اقتراح إنجليزي من قاموس قطع شائعة** اقتراح محلي لأسماء مطابقة بالكامل، وليس ترجمة AI. تبقى الكميات والمواصفات والأسطر غير المعروفة للمراجعة.
4. اختر محلًا من دليلك، ثم جهّز رسالة واتساب بالقطع وVIN وراجعها قبل أن تضغط «إرسال» داخل واتساب.

من **المزيد ← محلات قطع الغيار** سجّل أسماء المحلات وأرقامها والماركات التي تخدمها. تأتي المحلات المتخصصة في ماركة السيارة أولًا، ثم المحلات العامة. هذه مطابقة لتخصصات محفوظة، ولا تؤكد مخزون المحل أو السعر أو موقعه.

**ترجمة AI غير متصلة.** تفعيلها الحقيقي يحتاج اختيار مزوّد وخادمًا موثّق الهوية ومفتاحًا محفوظًا على الخادم؛ GitHub Pages وحده لا يوفر ذلك، ولا يوضع المفتاح في المتصفح. تفاصيل قراءة VIN وحدود البحث ومتطلبات الربط في [دليل VIN وترجمة طلبات القطع](docs/ai-vin-setup.md).

## شعار الشركة حسب اسم السيارة

يظهر شعار الشركة المصنّعة الحقيقي في بطاقة السيارة، وتتغير المعاينة أثناء الكتابة في نموذج الاستلام وإضافة السيارة. تُطابق أسماء الشركات والموديلات الشائعة بالعربية والإنجليزية؛ مثل `نيسان ألتيما` و`Nissan Altima` أو اسم الموديل `Altima`. يتعرف التطبيق على 28 شركة: نيسان، تويوتا، BMW، هوندا، هيونداي، كيا، أودي، فولكس واجن، فورد، شيفروليه، ميتسوبيشي، مازدا، سوزوكي، سوبارو، رينو، بيجو، بورشه، تسلا، فولفو، جيب، إنفينيتي، كاديلاك، بنتلي، ميني، سكودا، رولز رويس، مرسيدس، ولاند روفر.

الشعارات من **Simple Icons 16.36.0**، مع نسختَي مرسيدس ولاند روفر من **11.15.0**، ومضمّنة محليًا في `assets/brands/` مع ملفات المصدر والترخيص. هي علامات الشركات، ولا تمثل صورًا فعلية لموديل السيارة أو سنة صنعها. عند عدم التعرف على الاسم يظهر رمز محايد مع طلب كتابة اسم الشركة. لا يستخدم التطبيق خدمة صور أو بحث خارجية، ولا يرسل الاسم الذي تكتبه إليها؛ تُجرى المطابقة على جهازك وتُحمّل ملفات الشعارات من الموقع نفسه. تفاصيل المصدر والترخيص في [توثيق الشعارات](assets/brands/README.md).

## إشعارات واتساب

- اضغط **واتساب: تم الاستلام** من بطاقة السيارة لإعداد إشعار استلامها للصيانة.
- بعد تحديد **السيارة جاهزة** يمكنك مراجعة إشعار الجاهزية أو فتحه لاحقًا من **واتساب: السيارة جاهزة**.
- في المعاينة اختر **العربية أو الإنجليزية** وراجع اسم العميل ورقمه ونص الرسالة المنسّق بالإيموجي، وعدّل الرقم أو النص عند الحاجة. تعديل الرقم هنا يخص هذه الرسالة فقط.
- اضغط **فتح واتساب للإرسال**، ثم اضغط **إرسال** بنفسك داخل واتساب. لا تُرسل رسالة تلقائيًا عند تغيير الحالة، ولا يسجّل البرنامج أن الرسالة وصلت أو قُرئت.

يمكن اختيار لغة الرسالة لكل أمر عند الاستلام. ومن **المزيد ← رسائل واتساب** يمكن تغيير اللغة الافتراضية أو تفعيل فتح المعاينة بعد الحفظ. التفضيلات محفوظة محليًا على هذا المتصفح، واختيار لغة الأمر يبقى معه في النسخة الاحتياطية. عند تبديل لغة المعاينة يحتفظ النص المعدّل بمسودة مستقلة لكل لغة أثناء فتحها.

تحتوي الرسالة على اسم الكراج والعميل والسيارة واللوحة ورقم أمر الصيانة. تُقبل أرقام الإمارات المحلية مثل `0501234567`، والأرقام الدولية التي تبدأ بـ `+` أو `00`، وكذلك الأرقام العربية والفارسية. أضف رمز الدولة للأرقام غير الإماراتية. يتحقق البرنامج من تنسيق الرقم؛ لا يستطيع تأكيد أن الرقم مسجل في واتساب أو أن العميل قرأ الرسالة.

**الإرسال التلقائي غير متصل في النسخة الحالية.** فتح معاينة رسالة الاستلام تلقائيًا بعد الحفظ لا يرسل الرسالة؛ يبقى الضغط على «إرسال» داخل واتساب مطلوبًا. لا يحتاج إعداد الرسائل الحالي إلى مفاتيح API.

الإرسال الحقيقي عند حفظ الاستلام يحتاج **WhatsApp Business Platform / Cloud API** ورقمًا مفعّلًا وقوالب Utility معتمدة بالعربية والإنجليزية وخادمًا موثّق الهوية وقاعدة بيانات وطابور إرسال دائمًا. تطبيق WhatsApp Business وحده لا يوفر هذا الربط؛ يلزم التحقق من دعم الرقم الحالي للهجرة أو Coexistence لدى Meta أو المزوّد.

انظر [خطة الربط التلقائي وقوالب الرسائل المقترحة](docs/whatsapp-automation.md) للمتطلبات والأمثلة القابلة للمراجعة. القيم السرية تُضاف إلى إعدادات الخادم الآمنة فقط، ولا تُرسل في المحادثة أو تُحفظ في المتصفح أو المستودع. لم يتم ربط حساب إرسال أو إجراء اختبارات رسائل حية ضمن هذه الوثيقة.

## الوظائف

- تسجيل العملاء وربط سياراتهم بهم، والبحث بالاسم والهاتف واللوحة.
- تسجيل قطع الغيار وتكلفة شرائها وسعر بيعها وتوريد كميات جديدة.
- إصدار أمر صيانة مع فاتورة، واختيار قطعة واحدة وكمية لكل أمر في هذه النسخة.
- خصم المخزون عند إصدار الفاتورة، ومنع إصدارها عند نقص الكمية.
- إصدار عروض أسعار لعميل مسجل أو ببيانات يدوية دون تسجيله، دون خصم المخزون أو إدراجها ضمن الإيرادات.
- متابعة حالة الصيانة وتسليم السيارة، وتسجيل دفعات جزئية أو كاملة وإلغائها مع سجل محفوظ، وإظهار المتبقي على البطاقة والطباعة.
- متابعة مستحقات العميل حتى بعد تسليم السيارة، مع تذكيرات قابلة للتأجيل ومسودات واتساب عربية وإنجليزية.
- إدارة العمال ورواتبهم الشهرية ودفعاتهم وخصوماتهم، وتذكيرات انتهاء الإقامة وبطاقة العمل.
- إعداد رسائل استلام السيارة وجاهزيتها مع مراجعة الرقم والنص قبل فتح واتساب.
- طباعة عروض الأسعار والفواتير بالعربية أو الإنجليزية أو اللغتين، مع وصف إنجليزي يدوي اختياري. من مربع الطباعة يمكنك اختيار PDF إذا كان جهازك يدعمه.
- ورقة صيانة تتضمن بيانات VIN وقائمة طلب قطع عربي/إنجليزي ودليل موردين حسب الماركة.
- تسجيل المصاريف وحساب الإيرادات وتكلفة القطع والربح التقديري والمبالغ غير المحصلة.
- تصدير واستعادة JSON مع فحص بنية الملف وتأكيد استبدال البيانات.

تظهر بيانات تجريبية عند أول فتح. لمسحها اختر «المزيد ← النسخ الاحتياطي ← مسح البيانات» ثم «مسح البيانات والبدء من جديد».

## البيانات والحسابات

تُحفظ البيانات في localStorage داخل المتصفح وعلى عنوان الموقع نفسه. تستخدم الواجهة الجديدة مفتاح التخزين السابق `zakher-garage-v1` وتحافظ على بيانات النسخة السابقة عند تحديث الموقع على العنوان نفسه. VIN والسنة والمحرك والوقود ولغة المستند ووصفه الإنجليزي ومسودة طلب القطع ودليل الموردين وبيانات العرض اليدوي والدفعات والتسليم والتذكير والعمال والرواتب حقول اختيارية؛ تُحفظ في النسخ الجديدة، وتُقبل النسخ السابقة التي لا تتضمنها دون مسح بياناتها. الفاتورة القديمة التي تحمل علامة مدفوعة تبقى مدفوعة بالكامل دون اختراع تاريخ دفع لها. الصورة المستخدمة لقراءة VIN لا تُحفظ ضمن النسخة الاحتياطية. لا تنتقل البيانات تلقائيًا بين الآيفون والكمبيوتر أو بين المتصفحات، ولا تُرفع إلى GitHub. صدّر نسخة من صفحة النسخ الاحتياطي ثم استوردها على الجهاز الآخر عند الحاجة؛ الاستيراد يستبدل بياناته. احتفظ بالنسخ التي تتضمن بيانات العملاء والعمال في مكان خاص وخارج المستودع.

الإيرادات هي قيمة جميع الفواتير قبل ضريبة القيمة المضافة، سواء دُفعت أم لا. الربح التقديري = الإيرادات − تكلفة القطع المباعة وقت الإصدار − المصاريف اليدوية − دفعات الرواتب المصروفة. تكلفة القطع محفوظة وقت الإصدار ولا تتغير بتغيّر سعر المخزون. غير المحصل هو مجموع المبالغ المتبقية بعد الدفعات الفعلية غير الملغاة، ويشمل السيارات المسلّمة. الضريبة التجريبية ثابتة عند 5%، والمستندات ليست فواتير ضريبية معتمدة. لا تتضمن النسخة مرتجعات أو خصومات على الفواتير أو عدة قطع في الفاتورة الواحدة. تطوير الإنتاج يتطلب قاعدة بيانات ومصادقة وصلاحيات ونسخًا احتياطية مركزية وتدقيقًا محاسبيًا.

تغطي الاختبارات خصم المخزون والضريبة وتثبيت التكلفة، استبعاد عروض الأسعار، منع نقص المخزون دون تغيير جزئي، رفض المدخلات الخاطئة، حساب الربح والتحصيل، وصحة النسخ الاحتياطية، وتنسيق أرقام واتساب وترميز نص الرسالة، وتعديل التكاليف والقطع دون تغيير جزئي أو تعديل فاتورة مدفوعة، ومطابقة شعارات الشركات وأسماء الموديلات بالعربية والإنجليزية والرمز المحايد للأسماء غير المعروفة، وحقول الموردين وVIN الاختيارية وصياغة طلب القطع وترتيب الموردين. نتيجة الاختبارات تُقرأ من التشغيل الحالي؛ الاختبارات المحلية لا تثبت نجاح اتصال خارجي أو تفعيل AI.

اختبار متصفح اختياري (يتطلب Playwright وChromium). ثبّت أداة الاختبار خارج المشروع للمحافظة على عدم وجود تبعيات تشغيل:

```bash
npm install --prefix /tmp/zakher-test-tools playwright
PLAYWRIGHT_MODULE=/tmp/zakher-test-tools/node_modules/playwright node scripts/ui-test.cjs
PLAYWRIGHT_MODULE=/tmp/zakher-test-tools/node_modules/playwright node scripts/workshop-ui-test.cjs
PLAYWRIGHT_MODULE=/tmp/zakher-test-tools/node_modules/playwright node scripts/operations-ui-test.cjs
```

شغّل `npm start` أولًا. لاختبار استضافة تحت مسار فرعي، عيّن `BASE_URL` إلى عنوانها الكامل المنتهي بشرطة مائلة، مثل `http://127.0.0.1:3001/Zakher-/`. يستخدم الاختبار Chromium المثبت في `/usr/bin/chromium`؛ يمكن تعيين `CHROMIUM_PATH` أو استخدام `CDP_URL` لمتصفح اختبار يعمل مسبقًا. الاختبار يستخدم سياق متصفح منفصلًا ولا يمس بياناتك. يغطي استلام سيارة جديدة أو مسجلة والفاتورة والمخزون والدفع وإتمام الصيانة وعرض السعر والحفظ بعد التحديث والمصروف والطباعة والتصدير والاستيراد وعرض 390 بكسل، إضافة إلى معاينة رسائل واتساب والتحقق من الرقم والنص والرابط دون إرسال رسائل فعلية. محاكاة عرض الهاتف لا تعادل اختبار Safari على آيفون فعلي.

اختبار `operations-ui-test.cjs` يغطي العرض اليدوي دون وجود أي عميل أو سيارة، وطباعة العرض وتعديله، والسداد الجزئي والكامل ومنع الدفع الزائد وإلغاء الدفعات، والتسليم مع بقاء الدين وإلغائه، والرواتب والخصومات وحفظ الراتب لكل شهر واحتساب المصروف، وتنبيهات الإقامة وبطاقة العمل وتأجيل متابعة المديونية، والتصدير والمسح والاستعادة وحفظ جميع الحقول الجديدة. تُختبر النوافذ بالعربية والإنجليزية بعرضَي 390 و320 بكسل دون إرسال رسائل خارجية.

## حفظ التعديلات في GitHub

من مجلد المشروع، راجع الملفات أولًا ثم أنشئ فرعًا واحفظها:

```bash
git status
git switch -c feature/zakher-demo
git add .gitignore README.md package.json server.js static-files.js index.html app.js domain.js ledger.js operations-ui.js vehicle-art.js procurement.js vin.js i18n.js workshop.js style.css assets vendor docs tests scripts
git commit -m "Add Zakher garage demo"
git push -u origin feature/zakher-demo
```

إذا طلب Git اسمك وبريدك، اضبط `git config user.name` و`git config user.email` محليًا بهويتك الصحيحة ثم أعد أمر commit. لا تضع مفاتيح أو كلمات مرور داخل الملفات. افتح المستودع `mhmdro/Zakher-` على GitHub ثم أنشئ Pull Request إلى `main` إذا كانت موجودة. إذا كان المستودع بلا أي commits أو فرع main، يمكنك بعد أول commit استخدام `git branch -M main` ثم `git push -u origin main` لإنشاء أول فرع بدل أمر push السابق.

حفظ الكود في GitHub وحده لا ينشر الموقع ولا يحفظ سجلات العملاء. نشر الموقع يتطلب تفعيل GitHub Pages ورفع ملفات الاستضافة كما في القسم التالي.


## النشر على GitHub Pages

المشروع يعمل كملفات ثابتة دون خادم Node.js في الاستضافة. جهّزها بالأمر:

```bash
npm test
npm run build
```

ينتج `dist/` وفيه ملفات الواجهة والوحدات المحددة في قائمة البناء، و`.nojekyll`، وشعارات الشركات المحلية في `assets/brands/`، وخطوط Tajawal المحلية في `assets/fonts/`، ومحرك OCR وملفات اللغة المحلية في `vendor/ocr/` و`assets/ocr/` مع ملفات المصدر والترخيص. تظهر قائمة البناء وعدد الملفات عند تشغيل الأمر؛ لا تُنسخ المجلدات عشوائيًا. لا يلزم تثبيت حزم npm لتشغيل الموقع المنشور. توثيق مصدر Tesseract وترخيصه في `vendor/ocr/README.md`، وتوثيق الشعارات والخطوط في مجلديهما.

لا يتضمن التصدير بيانات المتصفح أو سجلات العملاء التي أدخلتها أو ملفات الخادم والاختبار أو أي أسرار وبيانات اعتماد. البيانات المرفقة في المصدر أمثلة تجريبية؛ لا ترفع ملفات النسخ الاحتياطية التي تتضمن بيانات حقيقية إلى المستودع. مسارات الأصول نسبية لتعمل تحت مسار المستودع.

يحتفظ فرع `main` بالمصدر، وفرع `gh-pages` بملفات الموقع الجاهزة. بعد رفع فرع `gh-pages` افتح إعدادات المستودع → Pages، واختر:

- Source: **Deploy from a branch**
- Branch: **gh-pages**
- Folder: **/ (root)**

احفظ الإعدادات وانتظر نجاح بناء Pages. يظهر الرابط الفعلي في صفحة الإعدادات نفسها. لا يعني رفع الفرع وحده أن الموقع أصبح متاحًا؛ يجب نجاح بناء الاستضافة. لا تغيّر خصوصية المستودع أو تشترك في خطة مدفوعة تلقائيًا؛ تحقق من توفر Pages في خطة حسابك إذا كان المستودع خاصًا.

لتحديث الموقع لاحقًا، احفظ تغييرات المصدر في `main`، أعد الاختبارات و`npm run build` ثم حدّث محتويات فرع `gh-pages` بكامل ناتج `dist/`، بما فيه مجلدا الشعارات والخطوط وملفات المصدر والترخيص. الكود المنشور لا يزامن بيانات المتصفحات؛ استخدم التصدير والاستيراد لنقلها.
